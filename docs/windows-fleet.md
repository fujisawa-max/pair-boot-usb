# WindowsでPC登録台帳を回収・統合・配布する

1台のWindows管理PCで、複数USBの登録情報をまとめられます。管理PCは未登録・NVIDIA GPUなしでも構いません。各対象PCでFedoraによる新規登録を済ませた台帳を使います。この手順では管理PCを新たに登録せず、MOK、root、state、Modelsもコピーしません。

0.9.1のWindows管理GUI／`tools/fleet.ps1` は通常GPUとGPUなしTESTの登録を扱います。対応する版変換は `0.9.0-shared` → `0.9.1-shared` です。0.8以前の設定移行や0.9.1→0.9.0への逆変換には使用しません。TESTを配布しても推論可能にはならず、TEST起動は明示的に選択する必要があります。

## 1. 各USBから回収する

1. PAIRが終了し、利用中のroot・stateが安全に閉じられたUSBをWindows管理PCへ接続します。
2. エクスプローラーで **GPU-LOGS** を開き、そのUSBの `MEDIA-INFO.txt` とドライブ文字を確認します。0.9.1の `gui/windows-gui.ps1` をWindows PowerShellから起動します。起動方法は[利用開始](quick-start.ja.md)を参照してください。
3. 「設定USB（GPU-LOGS）」で回収元を選び、「USBから台帳回収」を実行します。保存先は管理PCの作業フォルダとし、`registry-usb-a.json` などUSBごとに異なる新しい名前にします。既存ファイルへは上書きしません。
4. 「PC登録一覧（台帳）を表示」で回収したJSONを選び、`generation`（世代）、`version`（版）、`hosts`（登録数）を控えます。
5. 他のUSBも同様に回収します。回収した元ファイルはバックアップとして保持します。

版の違うUSBを扱う場合も、ツールは0.9.1版を使います。回収時は選択したUSB自身の版と台帳の版を照合します。登録済みUSBの `usb-config.json` や登録情報を手入力で書き換える必要はありません。

## 2. マージする

1. 「設定USB（GPU-LOGS）」に配布先の0.9.1 USBを選びます。選んだUSBの版を統合先の版として使います。この段階ではUSBの台帳は変更しません。
2. 「マージ後の世代番号」に、**統合元のすべての台帳と全配布先の現在の世代より大きい整数**を指定します。たとえば最大が7なら8です。配布先にも未回収の変更がある場合は、その台帳を先に回収して統合元に加えます。
3. 「台帳をマージ」を選び、回収した複数のJSONを選択します。出力は `registry-merged-8.json` などの新しいファイルにします。
4. 確認画面で統合元の台帳、統合後の保存先、選択USBを確認して実行します。結果の登録数、世代、版が想定どおりか、「PC登録一覧（台帳）を表示」でも確認します。

USBを未選択でマージした場合は、統合元の台帳が同じ版、または対応する前進方向の版の組合せであることを確認して統合先を決めます。配布先の版を明確にするため、通常は対象USBを選んでください。台帳が1つだけならマージを省略して配布できます。

同一PCで保存先やGPUなどの登録内容が異なる場合は競合として停止します。同じ登録内容の確認日が異なる場合は、統合元の台帳のうち新しい実際の確認日を保持します。マージした日時を新しい確認日として使うことはありません。

## 3. 各USBへ配布する

1. 「設定USB（GPU-LOGS）」で配布先を選びます。
2. 「USBへ台帳配布」で統合JSONを1つ選び、確認画面の対象USBと配布する台帳を確認して実行します。
3. 「USBから台帳回収」で別名に再回収し、「PC登録一覧（台帳）を表示」で世代、版、登録数を照合します。対応する版変換を配布時に行った場合は、世代が1つ増えます。
4. すべての0.9.1 USBへ繰り返します。ファイルを閉じ、Windowsの安全な取り外しを行います。Fedoraへの再起動は不要です。

配布は `gpu-config/registry.json` と `gpu-config/hosts/*.env` を整合する形で生成します。`registry.json` の直接上書きだけで代用しないでください。世代の巻戻し、同じ世代で内容が違う台帳、既存PCの削除や保存先変更は拒否します。期限切れ、BitLockerのUnknown、未確認の安全属性などでも停止します。停止理由を解決せずにJSONの安全値や確認日を手編集しないでください。

台帳を配布しても、登録先NTFSの識別情報はそのままです。USB保存先に登録した領域が別のUSBにある場合、その保存用USBも起動時に必要です。台帳の配布だけで別のUSB領域へ保存先が切り替わることはありません。

## 配布結果を確認する

配布後は次を確認します。

- 未登録・GPUなしのWindows管理PCから、GPU-LOGSだけを対象に回収・マージ・配布できる。
- 配布後の再回収で世代・版・登録数が一致し、同じ統合台帳の再配布でも登録が失われない。
- 通常GPUのPCはNormal／対応するUnlockで、GPUなしのPCは明示したTESTで起動できる。
- 正規に登録した0.9.0台帳を0.9.1 USBへ配布でき、登録先と確認日を引き継ぐ。台帳変換とroot更新は別の処理として確認する。

競合や破損の拒否試験は `python3 scripts/run-tests.py` の合成fixtureで行います。実USBの台帳を故意に壊して試す必要はありません。MOK登録は各PCで別途確認します。
