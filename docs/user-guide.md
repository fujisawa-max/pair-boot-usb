# 運用・モデル・終了・回復

## PCと保存先の登録

Windowsで候補JSONを集め、各対象PCのFedoraで実機情報と照合して登録します。PC登録一覧の本体はGPU-LOGSのgpu-config/registry.jsonです。複数USBでは台帳を回収・マージし、管理GUIの配布操作で各USBへ反映してhostsも再生成します。別PCの登録を手入力で流用しません。

USBを書き直す前に候補JSONと台帳を退避します。復元は退避台帳を別名でUSBへ置き、管理GUIの配布操作を使います。古いusb-config.json、証明書、gui、toolsで新USBを上書きしません。

## root・state・Models

選択したNTFS領域の既定フォルダはGPU-Linuxです。登録時に変更できます。root.img、state.img、各管理用metadata、Modelsを使用します。0.9.0ではrootは6GiB、初期stateは1GiBです。初回コピー用に合計7GiBと1GiB以上の予備容量を用意し、更新・回復・キャッシュには追加の空き容量を確保します。初回Normal起動でフォルダを作らせ、正常終了した後でモデルをコピーする順序を推奨します。root.img、state.imgや管理ファイルをモデルコピーの際に上書きしないでください。

/modelsは登録先のModelsを読み取り専用で公開します。画像モデルのGGUFとmmprojは対応する組み合わせをモデルごとのサブフォルダへ置きます。mmprojのファイル名はmmprojで始めます。モデルを追加したら推論エンジンを再起動して一覧を確認します。

開発者PCでもPAIRを起動し、推論ノードと同じクラスタへ参加させます。通常のllama.cpp接続先は、その開発者PCの http://127.0.0.1:8080/v1 です。APIに送るモデル名は/v1/modelsで確認します。モデル名、コンテキスト上限、画像・ツール対応はクライアント設定と実際のエンジンを揃えます。

## 設定の保持とroot交換

0.9.0は新規導入用の試作版です。0.8以前からの自動設定移行はありません。既存データを残し、新しい保存先フォルダへ登録してください。

PAIRの設定・クラスタ情報・起動ON/OFFとホームはstate.imgに保存します。PC固有のLinux識別情報もstateへ保存します。PAIR本体と固定llama.cppはroot内の/optにあり、設定領域に実行ファイルを持ち越しません。stateにはPAIRが生成する秘密情報も入るため、Gitやログ添付へ追加しないでください。module署名用の秘密鍵はstateへも置きません。

起動バナーには現在のrootの版と実際のNormal/Unlockを表示します。PAIRを終了して3択メニューへ戻った場合も再表示します。

対応する新版USBで、登録先のrootが異なる版または同じ版の別ビルドだった場合は、起動途中でroot交換を確認します。交換する場合だけコンソールで `UPDATE` と入力します。新rootをコピー・検証し、旧rootとreceiptをroot-before-update-*へ退避します。stateとModelsは交換しません。キャンセル時は旧rootを変更せず起動を停止します。旧rootの起動には対応する旧USBが必要です。旧版へのdowngradeは受け付けません。

旧rootを残すことだけではrollbackの保証になりません。新版PAIRがstateの形式やクラスタ状態を更新した場合、旧rootでそのまま利用できないことがあります。状態のbackup/復元はクラスタとの整合性も含めて判断します。

PAIRは専用サービスでgpuユーザーとして実行します。終了時にサービスの子プロセスも終了させます。後片付けを確認できない場合は再起動を拒否します。PAIR内部のサービスが異常終了しエンジン操作ができなくなった場合は、一度PAIRを終了してメニューから再起動します。それでも起動を拒否されたらPCの正常な再起動を行い、原因を確認してください。この異常終了経路の実機検証は未完了です。

固定エンジンの更新はroot交換で行います。PAIRからの固定エンジンのアンインストールは管理領域外として拒否されます。試作版ではPAIRのデータ全消去・初期化操作と追加エンジンの導入は検証対象外です。

## 終了とUSBの取り外し

現在の構成ではPAIRの操作画面をtty1、保守用の物理rootコンソールをtty2に配置します。保守コンソールにはパスワードを設定していません。対象PCの物理アクセスを管理できる環境で使用します。SSHログインは既定で無効です。

PAIRをqで終了すると、PAIR再起動、PC再起動、電源断のメニューへ戻ります。完了前に電源を強制的に切らないでください。

USB CAN BE REMOVED NOWの表示がある場合のみ起動USBを取り外せます。root/Modelsを保存する別USBは接続したままにします。Fedora Liveの起動USBは稼働中に取り外しません。

## 停止・回復

安全性を確認できない保存先や、登録のないPCでは停止します。BitLockerや高速スタートアップの状態、PC識別情報、選択した領域を確認します。確認できない状態をOff等に手入力して通さないでください。

root.imgまたはstate.imgの回復が必要な場合は、元を保持しコピー上でfsckします。追加の容量が必要です。回復できない場合や取引が中断した場合は停止し、Fedoraで確認します。root-backup-*、state-backup-*、.root-maintenance.*、.state-maintenance.*、.root-replace.*、receiptを理由なく消さず、元イメージを保持します。NTFSをマウント中のrootイメージへ手動でfsckしません。

ログを共有するときはUUID、ホスト名、ネットワーク、登録情報等を除いた必要な部分に絞ります。鍵や認証情報は共有しません。
