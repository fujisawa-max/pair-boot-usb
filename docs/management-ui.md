# Windows・Fedoraの管理ツール

0.9.3の管理ツールは、操作をカテゴリ別に分け、必要な項目だけを表示します。表示言語は実行環境に応じて日本語または英語へ自動切替します。PC名やフォルダ名などのデータは翻訳しません。

候補情報、BitLocker確認情報、回収した台帳は、既定で **GPU-LOGSの `data/` フォルダ**へ保存します。台帳のマージ・形式変換・PC名更新で作るJSONは、Windows・Fedoraともに `gpu-config/` が既定の保存先です。Windowsでは保存ダイアログで別の場所も選べます。Fedoraの出力はこの起動USB内へ保存します。以前USB直下や `data/` へ保存したJSONも引き続き選択できます。起動に使う台帳本体は従来どおり `gpu-config/registry.json` です。

## Windowsで操作する

上部のタブを選び、その中の操作を選択します。

| タブ | 操作と用途 |
| --- | --- |
| PC情報の取得 | 「候補情報を保存」で、このPCのWindowsのPC名、NTFS保存先、BitLockerの観測情報等を保存します。「BitLocker観測を保存」は通常観測だけを別に取得する補助操作です。 |
| 台帳管理 | PC名による一覧表示、USBからの回収、複数台帳のマージ、USBへの配布、旧台帳の形式変換、PC名の追加・更新を行います。 |
| 診断・詳細確認 | 読み取り専用の環境確認、管理者権限での詳細情報・BitLocker確認JSONの取得を行います。 |

「保存先NTFSドライブ」と「保存先フォルダ名」は、PAIR BOOTのroot/state/Modelsを置く場所です。保存先がUSB上にある場合は「USB上の場合はチェック」を選択します。「出力JSON」は今回取得・作成する情報を書き出す先で、別の項目です。台帳の回収やマージにrootの保存先を指定する必要はありません。

「PC登録一覧を表示」「台帳をマージ」「USBへ台帳配布」「旧台帳を形式2へ変換」「PC名を追加・更新」の台帳JSONの選択は、対象USBの `gpu-config/` から開きます。USBが `D:` なら `D:\gpu-config\registry.json` を選ぶと、そのUSBで起動に使う台帳を確認できます。回収・マージした台帳JSONを選ぶこともできます。マージ・形式変換・PC名更新の出力JSONも `gpu-config/` から保存先を選び、元の台帳とは別の新しいファイルに保存します。作成した台帳を起動に使うには「USBへ台帳配布」で反映してください。

処理の詳細な出力は通常の結果へ混ぜず、「診断情報をコピー」を押したときにクリップボードへ取り出せます。問題を調べるときは、この内容をテキストファイルなどへ貼り付けて確認してください。自動保存や外部への送信は行いません。

BitLockerの通常観測がUnknownの場合は、管理者用のBitLocker確認JSONを取得し、Fedoraの登録で別の確認情報として選択します。管理者向けの情報取得だけにUACの承認を求めます。GUI全体を管理者として起動する必要はありません。暗号化や高速スタートアップの設定は変更しません。

## Fedoraで操作する

最初にカテゴリを選び、次に操作を選びます。操作に必要な選択・入力・確認だけが順番に表示されます。操作選択の取消ではカテゴリへ戻り、カテゴリ選択の取消で終了します。

| カテゴリ | 操作と用途 |
| --- | --- |
| PC登録 | Windows候補と、このPCのGPU・保存先を照合して登録します。通常GPUとGPUなしTESTを分け、TESTではGPUの選択を求めません。 |
| 台帳管理 | PC名を中心とした一覧と詳細表示、回収、マージ、配布、旧形式の変換、PC名の追加・更新を行います。 |
| Secure Boot（MOK） | 公開証明書と登録状態の確認、登録・削除申請、各申請の取消を行います。パスワードは必要な申請だけで求めます。 |
| 診断・終了 | Secure Boot・GPU・領域一覧等の確認と、GPU-LOGSのアンマウントを行います。 |

操作対象は、そのFedoraを起動したUSBのGPU-LOGSです。候補・台帳等のJSONはGPU-LOGS内から選択します。MOKの登録・削除の最終承認は、再起動後のUEFI MokManagerで行います。

「設定領域をアンマウント」はGPU-LOGSだけを閉じます。Fedora Liveが利用中のUSB全体を取り外してよいという意味ではありません。

## PAIRに表示するPC名

台帳にPC名があれば、次回起動時に「整形したPC名＋ハードウェアUUID」をLinuxのhostnameとして設定し、PAIRの表示にも使います。例えば `LLM-PC-01` は `llm-pc-01-0123456789abcdef0123456789abcdef` のようになります。接尾辞にはハードウェアUUID全体をハイフンなしの32桁で付けます。

hostnameは英小文字・数字・ハイフンへ整え、全体を63文字以内に収めます。長い名前はPC名側を切り詰めます。変換後に使える文字がない名前には `gpu` を使い、UUIDを付けます。元のPC名は台帳にそのまま保持します。

PC名がない旧台帳を使う場合は、従来の `gpu-…` を維持します。名前の追加・変更は次回起動時に反映し、PAIR稼働中には変更しません。既存state、machine-id、PAIRのノードUUID・設定は初期化しません。

## 旧台帳の引継ぎとPC名の追加

0.9.3で作成する台帳の形式版は2です。形式1も読み込めますが、名前のないPCは「PC名未登録」と表示します。PC名は表示用の情報で、PCの一意識別には引き続きUUIDを使います。同名の別PCも区別されます。

### 名前を付けずに形式だけ変換する

1. 「台帳管理」から「旧台帳を形式2へ変換」を選択します。
2. 元の台帳JSONを選択します。
3. 元の世代より大きい新しい世代番号と、新しい出力JSONを指定します。
4. 内容を確認して保存します。元の台帳と、登録済みのGPU・保存先の情報は保持します。

### PC名を追加・更新する

1. 「台帳管理」から「PC名を追加・更新」を選択します。
2. 元の台帳JSONを選び、その台帳のPC一覧から対象PCを選択します。Fedoraでは「PCを選んで名前を編集」からPCを選びます。
3. PC名を手入力するか、「候補JSONから補完」で、新しいWindowsツールが取得した候補JSONを選択します。候補と選択PCのUUIDが異なる場合は補完しません。
4. 別のPCを選んで同様に編集します。編集中の名前はPCごとに保持し、選び直すと入力済みの名前が表示されます。Fedoraでは入力を確定すると編集メニューへ戻ります。
5. Windowsでは「確認して実行」、Fedoraでは「変更したPC名をまとめて保存」へ進み、元より大きい世代番号と新しい出力JSONを指定します。変更するすべてのPC名を確認し、1つの新しい台帳として保存します。世代番号はPCごとではなく、この一括保存で1つ進めます。

編集中の名前の保持は、同じ台帳を編集している間のものです。別の台帳へ切り替えたり操作を終了したりすると、未保存の編集は引き継ぎません。不正な名前・未登録PC・同じPCの重複指定などがある場合は、一部だけを保存せず停止します。作成した台帳は「USBへ台帳配布」で反映してください。

形式1の台帳からPC名を追加する場合は、この操作で形式2として保存するため、先に形式だけを変換する必要はありません。Windowsで候補を取り直しても、名前の追加だけならGPU・保存先をFedoraで登録し直す必要はありません。

PC名の変更で起動先や保存先は変わりません。元の候補や台帳のUUID、安全情報を手編集して一致させる方法で代用しないでください。

### 作成した台帳をUSBへ反映する

1. 全配布先の現在の台帳も回収し、世代と内容を確認します。
2. 複数台帳を統合する場合は「台帳をマージ」を使い、全入力と全配布先より大きい世代で保存します。
3. 「USBへ台帳配布」で、作成した台帳を対応USBへ反映します。Fedoraでは現在の起動USBが配布先です。
4. 再回収してPC名・形式版・世代・登録内容を確認します。

形式2は0.9.3の起動処理に対応しています。0.9.2以前のUSBへ配布しようとすると停止するため、先にUSBを更新してください。形式1の読み込みや変換は、元ファイルを残して行います。USBの全体イメージを書き直す前には、台帳と必要なユーザーデータを[バックアップ](user-guide.md#usbを書き直す前のバックアップ)してください。

同じUUIDでPC名が異なる台帳をマージするときは、どの名前を採用するかを確認して「PC名を追加・更新」でそろえてください。GPU・保存先の競合、世代の巻戻し、同じ世代で異なる内容、既存PCの削除は引き続き拒否します。

初回セットアップは[クイックスタート](quick-start.ja.md)、台帳の運用は[Windowsでの台帳管理](windows-fleet.md)、起動後の運用は[利用方法](user-guide.md)を参照してください。
